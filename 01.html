01 · kiindulási állapot

Mielőtt bármit átállítasz, mérd fel, hol tartasz

Ez a fejezet nem optimalizál semmit — állapotot rögzít. A cél egy olyan pontos kép a gépedről és a jelenlegi teljesítményről, amihez a következő fejezetek minden módosítását vissza tudod majd mérni.

Hardver Driver Hőmérséklet Órajel FPS/frametime Kihasználtság Baseline
01.1

Hardver felismerése

CÉL Pontosan tudni, mi van a gépben, mielőtt bármit módosítunk — mert a legtöbb tanács hardverfüggő.

→ CPU / GPU / RAM / alaplap pontos modellje, BIOS verzió stb. — minden információ kigyűjtésére a HWiNFO64 vagy a CPU-Z ajánlott
→ RAM: csatornakiosztás (single/dual channel), tényleges frekvencia — nem csak amit a gép kiír, érdemes a gyártó oldalán is megnézni
→ Tárhely: SSD vagy HDD, NVMe vagy SATA
→ Notebooknál külön fontos: van-e hibrid GPU (Optimus / Advanced Optimus) — ez befolyásolja a driver-beállítások egy részét
HWiNFO64 CPU-Z
01.2

Driver állapot

CÉL Egy elavult vagy hibás driver önmagában is okozhat teljesítményproblémát, mielőtt bármit tweakelnénk.

→ GPU driver verzió + kiadási dátum (NVIDIA / AMD / Intel)
→ Chipset driver — alaplapnál/notebooknál kritikus
→ Hálózati kártya driver
→ Javaslat: tiszta GPU driver cseréhez, ha gyanús a jelenlegi állapot
DDU — Display Driver Uninstaller
⚠
A Driver Booster és hasonló automata driver-frissítő programok kerülendők — 99%-ban elavult vagy nem megfelelő drivert fognak felrakni.
01.3

Hőmérsékletek

CÉL Baseline hőmérséklet terhelés alatt és nyugalomban, hogy lásd, van-e már itt szűk keresztmetszet (throttling).

→ CPU / GPU hőmérséklet terhelés alatt — sensor logging, vagy játék közben is monitorozható
→ Van-e throttle esemény (csökkenti-e a CPU az órajelét hő miatt)
→ Notebooknál: az alaplap / VRM hőmérséklete is releváns lehet
HWiNFO64 MSI Afterburner
💡
Ha régen volt már, vagy magas a kiindulási hőmérséklet, mindenképp érdemes egy gép-takarítás és újrapasztázás — ez stabilabb alapot ad, és önmagában is okozhat teljesítménynövekedést. Emellett a hardver élettartamát is megnöveljük, ha hűvösebben jár.
01.4

Órajelek

CÉL Tényleges vs. elvárt órajel — sokszor a gép "alulteljesít" pusztán mert a boost nem tud rendesen felmenni, vagy mert sok gép gyárilag fojtva van.

→ CPU boost órajel terhelés alatt (single-core vs. all-core)
→ GPU core / memory clock terhelés alatt
→ Van-e clock throttle (hő, power limit, vagy voltage miatt)
01.5

FPS / frametime

CÉL Nem elég az átlag FPS — a frametime konzisztencia (1% low, 0.1% low) mondja meg, mennyire "sima" a játékélmény.

→ Élő monitorozásra a MSI Afterburner + RTSS páros ajánlott
→ Mérünk: átlag FPS, 1% low, 0.1% low, frametime graph
→ Érdemes kirakni a kijelzőre is: GPU temperature, GPU usage, GPU memory usage, GPU core clock, CPU temperature, CPU usage, CPU clock, RAM usage, framerate, frametime
→ Ugyanaz a teszt-jelenet / replay minden méréshez, hogy összehasonlítható legyen — erre alkalmas a Benchmark mód
MSI Afterburner RTSS
01.6

CPU / GPU kihasználtság

CÉL Eldönteni, hogy a rendszer CPU-bound vagy GPU-bound-e — ez dönti el, melyik fejezet (CPU vagy GPU) fog majd többet segíteni, és mire érdemes nagyobb hangsúlyt fektetni.

→ Kihasználtság % játék közben — HWiNFO64, Task Manager Performance fül, vagy Afterburner OSD
→ Ha a GPU 99% és a CPU 60% alatt van → valószínűleg GPU-bound
→ Ha fordítva → CPU-bound (ilyenkor egy GPU-upgrade nem sokat segítene)
HWiNFO64 Task Manager Afterburner OSD
01.7

Benchmark + baseline

CÉL Ez az a szám, amihez a fejezet végén minden módosítást vissza fogunk mérni.

→ Érdemes folyamatosan rögzíteni / felírni a mérési adatokat: átlag FPS, 1% low, hőmérsékletek, órajelek stb. — ebből fogjuk látni, mi változott
⚠
Tuning esetén érdemes a Benchmarkot a végére hagyni, és inkább rendes játék közben tesztelni — a játék hamarabb tud crashelni, ha túl lett húzva a rendszer.
